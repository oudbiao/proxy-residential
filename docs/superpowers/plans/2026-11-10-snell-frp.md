# Snell ShadowTLS multi-VPS deployment implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** One Japanese Mac Docker container connects independently to a configurable array of VPS relays; Surge manually chooses a Snell + ShadowTLS node.

**Architecture:** Each VPS runs frps with an independently generated private CA and token. A single Japanese container runs one sing-box process with separate Snell/ShadowTLS inbounds per VPS and one reconnecting frpc process per VPS. VPS_LIST holds a JSON array of {"tag":"香港A","connection":"proxyjp://..."} entries.

**Tech Stack:** Python standard library (3.9+ host, 3.13 container), OpenSSL, frp 0.72.0, sing-box 1.14.4, Docker Compose, launchd.

**Spec:** docs/superpowers/specs/2026-11-10-proxy-jp-design.md

## Global Constraints

- Surge Snell version=6 with mode=default, ShadowTLS version=3; sing-box Snell inbound version=6 and mode=default. Snell PSK must be12–255bytes. User latest instruction supersedes earlier v4/v5 choice.
- Default proxy TCP 8443, tunnel TCP 7000, ShadowTLS handshake www.cloudflare.com:443; initialization can override.
- Japan one container, VPS_LIST JSON array in Compose with unique tags; independent credentials and frpc per entry; support 1, 3, 10 or more entries, no fixed three-slot limit.
- No public Japan ports, host networking, privileged mode, Docker socket, or TUN.
- Force and verify frp TLS; restrict frps allowed ports; no VPS direct fallback.
- Generated secrets excluded from Git, directories 0700, sensitive files 0600; initialization refuses existing output.
- User authorized deployment to a private VPS inventory; user explicitly requested final code/docs push to the supplied Git. Japan installation remains a portable handoff, with no installation or power/security changes on the development Mac.
- Latest Mac requirement supersedes Task2/Task4 login-only instructions: native Apple Silicon by default, environment detection and CLI Docker installation, system boot before login using dedicated Lima >=2.2. Task5/Task7 below replace that part of earlier tasks; Task6 adds GitHub/GHCR online distribution.
